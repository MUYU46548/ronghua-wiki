# 总则

为了增强知识库内部的逻辑密度，避免知识碎片化，本规范建议在文档末尾建立“相关文档”模块。

理论依据：主动链接>被动索引。本模块并非枯燥地制造全量索引，而是作者在完成记录后，基于主观判断对知识脉络进行的二次梳理。

# 价值说明

Obsidian原生的“反向链接面板”仅能展示“谁提到了我”（被动关联），手动添加的“相关文档”则表达了“我认为它与我有关”（主动关联）。这种做法具有以下优势：

* 隐性知识显性化：连接那些字面上不相似，但逻辑上相通的概念。
* 降低复用成本：在未来回顾时，无需在海量的反向链接中筛选，直接获取高价值关联路径。
* 强化思考深度：作为笔记收尾的仪式感，强迫大脑思考“该知识处于网络的哪个节点”。
* 增加写作自由度：不必在正文中通过遣词造句强制带出关联词，允许列出未在正文直接出现的关键词，打造有效内部链接。

# 实施规范

## 位置与格式

建议放置在文档正文的末尾，通常位于**其他资料**之前。如果模板中已有同功能模块，不要重复设置。使用一级标题，以保证视觉上的统一与醒目。

**推荐格式代码：**

```markdown
# 相关文档

- [[相关笔记A]]：简述关联原因。
- [[相关笔记B]]：简述关联原因。
- [[相关笔记C]]：简述关联原因。
```

## 链接分层策略

为了避免混淆，需区分“正文链接”与“底部链接”：

- 正文内嵌链接（强关联）：指上下文逻辑紧密相关，阅读时不跳转会影响理解的内容。
    - _示例_：在解释“原子笔记”概念时，直接链接到“卢曼卡片盒笔记法”。
- 底部相关链接（弱关联、拓展）：指同主题延伸、背景补充或对比阅读的内容。
    - _示例_：在写完一篇关于“番茄工作法”的实践后，底部链接到另一篇“GTD时间管理”的心得，作为横向对比。

## 填充原则

- 宁缺毋滥：不要为了凑数强行添加无关链接。如果确实没有想关联的内容，该模块可以留空。
- 数量控制：建议每篇文档关联**1-3**个核心文档。过多的链接会导致决策瘫痪，偏离“重点推荐”的初衷。
- 即时：写完笔记后立刻进行关联操作。依靠记忆中的“热度”去寻找关联，效率远高于日后的补录。

# 适用场景

- 适用：概念定义、设定资料、项目文档、杂谈论述。
- 不适用：索引（本模块在此为无关内容，影响链接统计）、单纯的日记流水账、极度碎片化的待办事项、设定碎片或草案。

# 维护与迭代

随着知识库的增长，旧的关联可能会失效或显得不再重要。在回顾旧笔记时，可以顺手更新该模块：

- 删除已经不再相关的链接。
- 补充新建立的、更紧密的知识链接。
