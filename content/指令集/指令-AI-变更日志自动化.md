# 变更日志自动化（基线快照对比法）

## 1.任务目标

自动检测角色文档的结构变化（新增或删除章节），并将变更摘要追加到变更日志中。

## 2.固定配置

- **所需工具**：本任务需调用文件读取、写入工具或执行 Python 脚本完成。
- **角色文档根目录**：`E:/图书馆/ROSA/03 设定/01 人物/02 新作人物/`
- **基线文件路径**：`E:/图书馆/ROSA/96 事务管理/结构基线.json`
- **日志文件路径**：`E:/图书馆/ROSA/96 事务管理/变更日志.md`

## 3.执行逻辑（纯机械，不涉及语义理解）

### 第一步：加载或建立基线

- 检查 `结构基线.json` 是否存在。
- **如果不存在（首次运行）**：
  1. 遍历角色文档目录下的所有 `.md` 文件。
  2. 对每个文件，提取：
     - `path`：文件路径（相对于角色文档根目录）
     - `mtime`：文件修改时间戳（数字）
     - `headings`：文件中所有二级标题的完整文本列表（**提取规则：严格匹配行首为 `##` 的文本行，忽略代码块内的内容**）
  3. 将上述信息保存为 JSON 格式写入 `结构基线.json`。
  4. 输出：`✅ 基线已建立，共记录 [N] 个文件。`
  5. **终止执行**（首次不生成日志）。

- **如果存在**：
  1. 读取 `结构基线.json` 内容，解析为对象。
  2. 继续执行第二步。

### 第二步：扫描当前状态并对比

1. 遍历角色文档目录下的所有 `.md` 文件，获取当前 `mtime` 和 `headings` 列表。
2. 对每个文件，与基线中存储的记录比较：
   - **若当前文件不在基线中** → 标记为 `新增文件`
   - **若基线中的文件在当前目录中不存在** → 标记为 `已删除文件`
   - **若 mtime 与基线一致** → 跳过（未变更）
   - **若 mtime 与基线不一致**：
     - 比较当前 `headings` 与基线中的 `headings`（行首严格匹配 `##`，忽略代码块内内容）。
     - 如果相同 → 标记为 `内容微调`
     - 如果不同 → 标记为 `结构变更`，并记录具体差异：
       - 新增了哪些标题
       - 删除了哪些标题
       - （可选）重命名的标题（通过相似度判断，但为避免幻觉，**本次不实现重命名检测，只报告增删**）

### 第三步：生成变更摘要并追加到日志

- 如果没有任何变更，输出：`✅ 自上次检测以来，无任何变更。` 并终止。
- 如果有变更，按以下格式生成摘要，**追加**到 `变更日志.md` 末尾（其中检测时间为**当前系统执行时间**）：

```markdown
📅 检测时间：YYYY-MM-DD HH:MM
🏗️ 结构变更
[文件名]：
新增了 ## 章节名A、## 章节名B
删除了 ## 章节名C
✏️ 内容微调（结构未变）
[文件名]：正文内容有更新
🆕 新增文件
[文件名]
🗑️ 已删除文件
[文件名]（请注意：若此文件已被手动删除或移动）
```

- 更新基线：将当前扫描结果（最新的 mtime 和 headings，并**剔除已删除文件的记录**）写回 `结构基线.json`，覆盖旧基线，为下次检测做准备。

### 第四步：输出摘要

在对话中输出简短摘要，例如：`✅ 检测完成。发现 2 个结构变更，1 个内容微调，无新增/删除文件。日志已更新至 变更日志.md。`

## 4.输出要求（省流模式）

只输出上述摘要，不输出详细的文件列表或完整 JSON 内容。

除非首次建立基线，输出：`✅ 基线已建立，共记录 [N] 个文件。`

## 5.执行模式

直接执行，无需人工预览确认（纯只读+追加写入日志，风险极低）。

首次运行自动建立基线，不生成日志。

请开始执行。
