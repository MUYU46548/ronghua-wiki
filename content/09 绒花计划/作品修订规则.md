- 核心理念：设定永远为叙事服务；承认过去，活在当下，拥抱未来。

# 一、基本原则

- 当设定矛盾无法完美调和时，选择最贴近史实的那一个。尤其是早期作品中，随意设计的成分较多，需要更加小心地处理。对于更早的作品（如旧作时段），如无把握，维持现状。新旧设定冲突时，以新设定为准
- 除风险项外，任何被否定的旧设定不直接从笔记中抹去，应留下有效备份版本，保留至专用区域供追溯
- 每次对设定做出重大调整（影响叙事理解或角色关系等），必须以适当形式留下注释记录：
	- 修改了哪些内容
	- 修改的原因（叙事需要、逻辑修复、早期笔误）
	- 新旧版本的简要对比

# 二、矛盾处理优先级

当两个或多个设定条目出现冲突时，按以下顺序处理：

1. 最新叙事作品中的描写：最近完成、修订的作品中的描写，自动覆盖所有旧设定。因为更新的版本更贴近目前的世界变化，且更先进的工具和技术有助于提高写作质量，完成修订审核工作
2. 年表或时间线中的明确记录：如果矛盾涉及事件发生的顺序或年代，以年表中的记录为准。实在无法解决的时序问题，在年表中另外记录（如条件允许）
3. 角色文档处理：由于角色文档存在滞后性，应先执行修订，后续将最新内容更新至相应文档中。与角色旧设定冲突时，以**当前状态**为准
4. 最早的原初设定（仅作参考）：如果以上三者均未覆盖，则保留最早的那个设定。因原始设定可能被后续叙事覆盖，其将继续存在被推翻的可能

# 三、原文保留与修改容忍度

- 已发布、公开的作品正文 / 完成全局修订后发送新版，风险项必须根除。 / 高
- 未发布的草稿、片段 / 可直接修改，通常无需在修订说明中记录，视情况留下注释即可。 / 高
- ROSA系统设定资料 / 可修改，但需要格外谨慎，以免改错内容引发连锁反应。主要依据（年表、基础概念）非必要不修改。 / 中
- 设定集 / 以批注为主，严格限制改动。旧设定本身也有参考意义。 / 低

对于**明显笔误或格式问题**，允许直接修正，无需单独在修订说明中记录。修订说明只书写宏观调整方向。

# 四、未来修订计划机制

- 每完成一个完整作品后，加入轮换池，根据轮环安排修订
	- 修订状态与优先级参考《修订计划表》（外置Excel，ROSA系统中无挂载）
	- 结合最新设定、资料，检查矛盾
    - 检查是否存在风险项
	- 确认是否需要仅进行流畅性调整，修改错字、标点、排版等
- 设定冻结机制
	- 在开始撰写一部重要新作品前，可选择“冻结”相关设定（角色、地理、关键事件）两周。冻结期内不修改这些条目，避免写作过程中基础信息变动
	- 期间依旧允许进行片段式记录
- 自我否定机制
	- 鼓励主动标记可能过时的设定。在任何文献中，如果觉得某条信息未来很可能被推翻，均可标记。推荐使用额外记录文本，避免直接在原始文件标记，保护原始文件

# 五、版本记录规范

- 所有修订必须统一编写修订记录，标题格式为`修订记录 YYYYMMDD`，其中`YYYY`为四位数年份，`MM`为二位数月份，`DD`为二位数日期，如`20200408`
- 修订版文件命名规范：`原书名_最后更新日期.pdf`，如`凛宴事记_20260604.pdf`。目前一般以PDF形态导出。
- 后续将对ROSA系统内已存档资料进行备份调整。初步计划为：保留所有原有文件名、路径不动，将内容额外复制一份，存放于专用备份文件夹中（具体文件夹名待定）。已修订内容直接覆盖原有文件。该操作不对现有引用链接造成任何干扰。若需修改文件名，必须审慎处理。备份的旧版文件必须进行合适标注，防止干扰引用（如添加前缀等）。旧版文件中的风险项必须予以根除
- ROSA系统资料具有滞后性，尤其是目录等信息。若发生不一致，以最新版修订为准。

# 六、资源部署策略调整

- ROSA系统之后将**不再搭载本地文字书籍资源**，已有的资源将随修订计划**逐步移除**，自本规则实施即时生效。旧版资源将在进行必要修改和调整后加入**旧资料存档**，之后不再保证维护。
- 原有的专用于链接引用的作品代码在OB30后**弃用**，之后的官方书籍仅拥有编号字段，不再单独编制代码。
- 如需获取文献资源，请关注后续调整说明。非授权的搬运行为均为盗版。
